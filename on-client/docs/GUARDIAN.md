# 알레프 수호령 마무리 기록

22단계까지 만든 케셰브를 내 PC에서 매일 쓰는 보안 앱으로 완성한 기록입니다. 각 일차 안내에 무엇을 했는지, 한계와 근거를 모았습니다.

## 핵심 기능 세 가지(1일차 선정)

| 메뉴 | 하는 일 |
|---|---|
| 보호 현황 | 현재 로그인·기기·세션을 확인하고 연결·AI 상태를 점검 |
| 업무 앱 | 앱별 접속 판정을 한 번씩 요청해 허용·차단·추가 확인을 확인 |
| 보안 기록 | 접속·XDR 기록을 보고 사건의 AI 설명과 조치 준비를 확인 |

프로젝트 재실행으로 22단계까지의 동작을 확인했고(`npm run demo`로 화면·경로 점검), 위 세 메뉴를 핵심으로 골랐습니다. 여기에 마무리로 **내 PC** 메뉴를 추가했습니다.

## 2~4일차: 내 PC 실측 화면

- **2일차** — CPU(os.cpus 누적 시간 0.25초 표본), 메모리(totalmem/freemem), 디스크(fs.statfs 시스템 드라이브)를 실측으로 표시합니다.
- **3일차** — 연결 상태(활성 IPv4 인터페이스 + DNS 확인 수준의 인터넷 여부), 방화벽(Get-NetFirewallProfile 읽기), 최근 이벤트(Get-WinEvent System 로그, 심각·오류·경고 12건)를 읽기 전용으로 표시합니다. 설정을 바꾸는 명령은 없습니다.
- **4일차** — 「다시 조회」 버튼으로 네 부분을 함께 다시 읽고, 조회 중·실패·비어 있음을 부분별로 표시합니다. 상단 「다시 불러오기」에도 내 PC 조회를 물렸습니다.

## 5일차: 실행 안내

README 「남이 따라하는 실행 안내」절이 그대로 따라하는 절차입니다: Node 24.19.0 → `tools\start-alekov.ps1`(또는 `npm start`) → `http://127.0.0.1:5189` → 「내 PC」 → 「다시 조회」. 외부 npm 의존성은 없습니다.

## 6일차: 포장 생략과 제출 커밋

안내에 따라 `npm run package-app`은 하지 않습니다. 제출물은 GitHub 저장소의 마지막 커밋 하나이며, 이 문서를 포함한 커밋의 `git rev-parse HEAD` 결과를 제출 창에 넣습니다.

## 7일차: 시연 절차 · 한계 · 근거

**시연 순서**
1. `npm start`로 켜고 `http://127.0.0.1:5189`를 엽니다(연결 없음이어도 됨. `npm run demo`면 예제 배지도 확인됨).
2. 「내 PC」를 엽니다. 자동으로 한 번 읽고, 「다시 조회」로 다시 읽습니다.
3. CPU·메모리·디스크는 이 PC의 실측값이고, 방화벽·이벤트가 Windows에서 읽은 실제 값임을 확인합니다.

**한계(정직한 범위)**
- 방화벽·이벤트는 **Windows 전용**이며 PowerShell의 `Get-NetFirewallProfile`·`Get-WinEvent`가 필요합니다. 다른 OS·명령 실패·시간 초과면 해당 카드만 `LOCAL_PLATFORM_UNSUPPORTED`/`LOCAL_*_UNAVAILABLE` 오류로 표시하고 나머지는 그대로입니다.
- 이벤트는 **System 로그의 심각·오류·경고 최근 12건**만입니다. 보안 로그는 읽지 않고, 이벤트 본문은 220자로 자릅니다.
- 인터넷 표시는 **DNS 이름 확인 수준**입니다(`www.msftconnecttest.com`). 실제 외부 접속 성공을 뜻하지 않습니다.
- CPU%는 0.25초 표본 평균이라 순간 피크와 다를 수 있습니다. 디스크는 시스템 드라이브 하나만 봅니다.
- 모두 **읽기 전용**입니다. 방화벽 켜기·끄기, 이벤트 삭제, 네트워크 변경 기능은 없습니다.

**읽기 근거**
- `src/local/status.mjs` — 수집기. Node 내장(os·fs.statfs·dns.lookup)과 powershell.exe 읽기 전용 명령만 씁니다.
- `GET /api/local/status` — 부분별 `ok`/`error`를 내려주고, 실패 부분에 가짜 값을 넣지 않습니다.
- 화면 `내 PC` — 부분별 조회 중·실패·정상을 따로 표시합니다.
