# 방어전 4~6차 제품 시작 틀 (v6)

3차까지 만든 자료실 위에, 실제로 운영할 수 있는 보안 운영 웹앱을 만듭니다. 이 틀에는 로그인 연결, 저장소, HTTP 경로 연결, 공개 시험이 들어 있습니다. 정책 판단, 사건 처리, 대응, 복구 같은 핵심 업무 코드는 여러분이 직접 씁니다.

학생이 돈을 낼 일은 없습니다. 유료 가입, 카드 등록, 개인 API 키 충전, 유료 호스팅, 도메인·장비 구매를 요구하지 않습니다. 유료 도구 사용이나 결제로 추가 점수를 주지 않습니다.

현재 r6 일정과 배점은 다음과 같습니다. 모든 날짜는 2026년 한국 시간 기준입니다.

| 차수 | 기간 | 필수 내용 | 제품 점수 |
|---|---|---|---|
| 3차 | 10/13~16 | 기존 6~12단계와 XDR 6개 필수 과제 | 기존 평가 기록으로 관리 |
| 4차 | 10/19~23 | D1~D4 실제 구현, v0.5 | 각 15점, 합계 60점 |
| 5차 | 10/26~27 | 총공세 통합·변경 요구 반영, v0.9 릴리스 | 통합·변경을 묶어 15점 + 릴리스 10점 |
| 6차 | 10/28~29 | 수복과 회귀 시험, v1.0 | 15점 |

제품 평가는 합계 100점이며 기존 19개 항목의 평가와 별개입니다. v1.0 제품 완료 여부는 서버의 실제 판정 기록으로 확인합니다. 3차 미완료 항목이 있어도 자료를 미리 보고 개발할 수 있습니다. 실제 차수 개시와 제출은 서버가 확인한 기간·개방 상태·권한에 따라 제한됩니다. 날짜가 됐거나 자료를 읽었다고 차수가 자동으로 시작되지는 않습니다. 자세한 안내는 [학생 안내서](docs/STUDENT_GUIDE.md)를 보세요.

## 1. 무엇을 만드는가

| 기능 | 하는 일 | 채울 함수 |
|---|---|---|
| D1 정책 | 정책 초안을 검사해 활성화하고, 바꾼 기록을 남기고, 예전 판으로 되돌립니다. 정책이 바뀌면 다음 요청부터 판정이 달라져야 합니다. | `decide` `getPolicy` `policyHistory` `createDraft` `activatePolicy` `rollbackPolicy` `readResource` `writeResource` |
| D2 사건 | 사건을 받아 중복과 충돌을 가려 저장하고, 시각 순으로 찾아보고, 짧은 시간에 몰린 읽기를 사건 묶음으로 만듭니다. | `ingestEvents` `queryEvents` `listIncidents` `getIncident` |
| D3 대응 | 대응을 제안하고, 사람이 승인한 뒤에만 집행합니다. 같은 요청이 두 번 와도 한 번만 집행하고, 실패하면 정해진 규칙대로 다시 시도합니다. | `createResponse` `approveResponse` `rejectResponse` `releaseResponse` `getResponse` |
| D4 복구 | 정책과 사건을 백업하고, 손상된 백업은 거부하고, 검증한 백업만 복원합니다. 감사 기록은 지우지 않습니다. | `createBackup` `restoreBackup` |

함수마다 지켜야 할 약속은 `src/product/index.mjs` 의 주석에 적혀 있습니다. 함수 이름과 입력·출력 모양은 바꾸지 마세요.

## 2. 폴더 안내

| 경로 | 누가 고치나 | 내용 |
|---|---|---|
| `src/product/index.mjs` | 학생 | 업무 코드. 여기만 채우면 됩니다. 파일을 나눠도 되지만 이 파일에서 내보내야 합니다. |
| `src/platform/` | 제공 | 로그인 확인, 경로 연결, 저장소·집행기 어댑터. 고치지 마세요. |
| `vendor/defense-product-contracts/` | 제공 | 정책 해시, 백업 형식, 작업 키 규칙. 직접 다시 만들지 말고 가져다 쓰세요. |
| `api/product/[...path].mjs` | 제공 | Vercel 서버 함수 진입점(기본 경로). |
| `scripts/serve-local.mjs` | 제공 | 내 PC 에서 띄우는 서버(대체 경로). |
| `supabase/product_kv.sql` | 제공 | 기본 경로에서 쓰는 저장 표. 내 프로젝트에서 한 번 실행합니다. |
| `supabase/product_operator.sql` | 제공 | 내 Supabase 프로젝트에서 본인 계정의 제품 operator 역할을 초기화하는 SQL 템플릿. 중앙 ALEPH DB에서 실행하지 않습니다. |
| `tools/event-generator.mjs` | 제공 | 연습용 합성 사건 생성기. |
| `public/console.html` | 학생이 키워 감 | 로그인과 정책 보기만 있는 시작 화면. 나머지 화면은 직접 만듭니다. |
| `templates/` | 학생이 채움 | CHANGELOG, 사후 보고서, 배포 안내 틀. |
| `test/public/` | 제공 | 공개 시험. |

## 3. 시작하기

```sh
npm test            # 공개 시험 22개. 미구현 업무 기능을 검사하는 시험은 실패하는 것이 정상입니다.
npm run test:d1     # 기능 하나씩 확인
node scripts/test-identities.mjs --local   # 내 PC 연습용 계정 A·B·OP 만들기
npm run start:local # 계정 생성 뒤 서버 띄우기(127.0.0.1:8787)
```

키트 폴더에서 위 명령을 실행하세요. 외부 패키지는 필요 없습니다. Node 20 이상이면 됩니다. 서버는 시작할 때 계정 파일을 읽습니다. 계정을 다시 만들거나 지울 때는 **서버를 먼저 중지하고** 아래 명령 중 필요한 것 하나를 실행한 뒤 `npm run start:local`로 다시 시작하세요.

```sh
node scripts/test-identities.mjs --local          # 연습 계정 다시 만들기
node scripts/test-identities.mjs --local --remove # 연습 계정 지우기
```

재생성하면 계정 ID와 비밀번호가 바뀝니다. 기존 연습 계정이 소유한 자료와 기존 로그인 토큰에는 그대로 사용할 수 없습니다. 출력된 연습용 비밀번호는 자기 PC에서만 사용하세요. 로그인 뒤 `/api/product/v1/me`로 역할을 확인할 수 있습니다. 업무 함수가 아직 비어 있으면 정책·사건·대응·복구 요청은 미구현 오류가 나는 것이 정상입니다.

## 4. 어디에서 돌리나

- **기본 경로:** 3차까지 쓰던 자기 무료 Vercel·Supabase 프로젝트를 그대로 씁니다. 새 프로젝트를 만들거나 플랜을 올리지 않습니다. 자기 Supabase의 서버 SQL 실행 환경에서 `supabase/product_kv.sql` → `supabase/product_operator.sql` 순서로 초기화합니다. operator 템플릿에는 **이메일 확인이 끝난 본인 계정 UUID**와 서버 환경변수 `PRODUCT_PROJECT_ID`와 정확히 같은 프로젝트 ID를 넣습니다. 중앙 ALEPH DB에서 실행하면 안 됩니다. 기존 로그인만으로 새 제품의 operator 역할이 자동으로 생기지는 않습니다.
- 서버 환경변수 네 개는 `SUPABASE_URL`, `SUPABASE_ANON_KEY`, `SUPABASE_SERVICE_ROLE_KEY`, `PRODUCT_PROJECT_ID`입니다. 자기 프로젝트의 서비스 키는 서버 환경변수에만 둡니다. 값은 브라우저·저장소·문서·채팅에 올리지 마세요.
- **대체 경로:** 무료 한도에 걸렸거나 프로젝트가 일시중지됐거나 계정에 문제가 있으면 3절의 계정 생성부터 진행해 내 PC에서 돌립니다. 판정 기준은 같습니다.

공식 시험 신원의 Supabase 등록 명령 `node scripts/test-identities.mjs --supabase --register`는 현재 구현이 완료되지 않았습니다. `ALEPH_IDENTITY_REGISTER_URL`을 설정해도 계정을 생성하지 않고 종료 코드 2로 끝납니다. 먼저 로컬 연습을 진행하세요. 개인 프로젝트 초기화가 운영 심판·집행 제공자·중앙 DB 연결 완료를 뜻하지는 않습니다.

## 5. 통과 기준

공개 시험을 통과했다고 끝이 아닙니다. 공식 판정은 시험 환경이 준비된 뒤 같은 약속에 새 값과 새 순서를 넣어 확인합니다. 공개 시험의 값에 맞춰 짠 코드는 통과하지 못합니다. 화면에 "성공"이 떴는지가 아니라 실제 요청의 결과와 저장된 기록으로 판정합니다. 운영 심판이나 제공자 연결이 준비되지 않아 확인하지 못한 항목은 미검증으로 표시하고 학생 실패로 세지 않습니다.
