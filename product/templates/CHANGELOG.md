# 변경 기록

판마다 무엇을 바꿨고, 어떤 시험으로 확인했는지 적습니다. 최신 판을 위에 씁니다.

## v0.5 (4차 마감)

- 추가한 기능:
  - D1 정책: 초안 생성·활성화(낙관 잠금, 동시 활성화는 하나만 성공)·판 이력·되돌리기(새 판 번호 + `rollback` 기록). 규칙 효과 `allow`/`deny`/`step_up`, 필드 method·zone·owner·role·와일드카드 존, priority·엄격함 순 판정, 미일치 기본 deny. operator만 정책 변경, 판 충돌 409.
  - D2 사건: 수집 시 같은 id·같은 내용은 duplicate, 같은 id·다른 내용은 conflict, 잘못된 배치는 전체 거부. 목록은 `at`→`id` 순. `burst_read` 탐지 — 창/건수를 `PRODUCT_BURST_WINDOW_MS`(기본 600000)·`PRODUCT_BURST_THRESHOLD`(기본 121) 환경변수로 조정 가능.
  - D3 대응: 작업 키 멱등(같은 키·같은 내용은 기존 결과 재사용, 다른 내용은 409), 승인 전 집행 금지, 동시 승인은 한 번만 집행, 실행기 실패는 재시도 가능(503·busy·timeout)과 영구 거부(403)를 구분, 응답 유실은 실행기 상태 조회로 회복(두 번 집행 안 함), release 멱등·기록. 승인 유효기간은 `PRODUCT_APPROVAL_TTL_MS` 환경변수로 조정 가능(기본: 만료 없음 → 시험 계약 유지).
  - D4 복구: 백업에 정책+선택 사건 포함, 반영 전에 백업을 먼저 검증(프로젝트 불일치·손상·금지 내용·사건 충돌 → 422로 전면 취소), 복원은 새 판 번호, 감사 이력 보존.
  - 실행 격리: `X-Aleph-Run-Id`별 `run:` 공간 분리, `/test/reset`은 그 공간만 지우고 감사는 유지. `X-Aleph-Executor-Grant`는 집행 어댑터에만 전달되고 업무 코드는 보지 않음.
- 고친 문제:
  - D1-3 공개 시험 실패 — 자원 쓰기 요청의 `owner`를 계약대로 `'self'`로 고정해 판정이 정책 변경을 즉시 반영하도록 수정.
- 확인한 시험: `npm test` → 22개 전부 통과(D1×6, D2×4, D3×6, D4×4, 실행공간 P×2). 로컬 서버 HTTP 실전 점검: 로그인→정책 활성화→자원 쓰기·읽기→사건 125건→`burst_read` incident→대응 승인·차단(403)·해제→백업→복원. `npm run check:platform` → 제공 파일 무결성 통과.
- 알려진 한계:
  - 공식 시험 신원 등록(`--supabase --register`)은 플랫폼 미구현(종료 코드 2) — 계약상 미검증 처리.
  - 공개 시험 통과는 공식 심판 판정이 아님. 새 값·새 순서의 판정은 심판 서버가 확인합니다.
  - 환경변수(버스트 창·건수·승인 만료)는 서버 재시작/재배포 후에 적용됩니다.
